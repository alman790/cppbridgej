# Stratawild 0.6 — background meshing and immediate distant terrain

Stratawild is an original C++20/Java voxel sandbox built as a CppBridgeJ demo. This version is an incremental update to **0.5**, not a new game engine or content pack.

## What changed

- **Independent detailed-mesh worker:** the simulation thread gathers at most four outstanding immutable snapshots (nine nearby loaded chunks per request). A C++20 `std::jthread` builds greedy opaque and water meshes, vertex AO and the 15-voxel halo lightfield without reading or mutating the live world. The GPU render thread only receives committed complete results.
- **Versioned completion:** every loaded chunk gets a unique generation ID and a monotonically increasing mesh epoch. If an edit, flowing water, a newly loaded neighbor, or unload/reload invalidates a snapshot, its result is discarded and the chunk is rescheduled. Work is bounded by an in-flight request limit and nearest-to-player ordering.
- **Near-border lighting invalidation:** block changes now dirty neighboring chunks within a conservative Manhattan halo of 15 voxels, not just blocks touching a chunk boundary. This fixes stale lighting caused by placing or removing lamps near chunk seams.
- **Immediate coarse fallback:** `voxel_mesh_list` now includes unmeshed chunks with revision 0 and no detailed quads. Their far-field heightfield was already generated by the terrain worker, so Java renders that as a temporary placeholder until the detailed mesh arrives. The existing ordered-dither near/far transition continues to operate once detailed meshes exist.
- **One synchronous bootstrap mesh:** the initial frame renders one nearby detailed chunk; subsequent detailed meshing is queued off-thread. GPU VBO management remains unchanged from 0.5.

## Compatibility

- **Saves:** `SVXL0002` remains readable and writable; back up `stratawild.svxl` before updating. Permanent user block edits and inventory remain intact. Flowing water is transient and re-simulated.
- **Bulk mesh ABI:** packed 8-byte quads and existing signatures are unchanged. **Behavior change:** the chunk list may include revision-zero entries with zero detailed quads. `voxel_mesh_copy_far` works at revision zero, while detailed and water copy calls still require a positive revision. Custom GPU consumers must handle this case.
- **Terrain:** same 0.5 deterministic generator; no breaking change to chunk positions or materials.
- **Software renderer:** still works through the same native API. Background detailed meshing mainly benefits the OpenGL client.

## Tests

- Existing 0.3, 0.4, and 0.5 native smoke, world generation, save, greedy-mesh, water and ABI tests remain in `test-native.sh`.
- New `world06.cpp` verifies cross-chunk light invalidation more than one block from the seam, asynchronous snapshot completion, stale edit result rejection, unload/reload generation checks and worker reset/restart.
- Native tests verified with GCC in this workspace; no production GPU benchmark or actual Mac M1 frame-time measurement is claimed.
- Full Java/Maven build and OpenGL runtime could not be exercised here (JDK 22+ and a GPU graphics context are not available). Test them on a desktop before distributing a binary.

## Performance scope and limitations

Off-thread detailed meshing **reduces main-thread meshing work**; it does not reduce the total CPU work of computing per-chunk light halos and may compete for CPU bandwidth on small systems. Copying neighborhood snapshots on the game thread still incurs memory traffic, limited to at most two dispatches per frame and four in-flight requests. Actual FPS improvement is unmeasured; record p95/p99 frame times before and after upgrading on the same hardware.

The initial 3×3 collision neighborhood is still generated synchronously. Coarse meshes omit caves, individual trees, water and player edits; crossfades can differ in silhouette and are not crack-free stitching. Lighting at the edge of unloaded world data is approximate and will re-resolve as neighbor chunks stream in. Fluid is a bounded relaxation, not a physically conservative volume simulation.

## Upgrade from 0.5

From the CppBridgeJ root, with Stratawild **0.5 already installed**:

```bash
git apply --check /path/to/stratawild-0.6-upgrade-from-0.5.patch
git apply /path/to/stratawild-0.6-upgrade-from-0.5.patch
bash cppbridge-voxel-demo/test-native.sh
bash cppbridge-voxel-demo/run-gpu.sh
```

For a clean clone, use `stratawild-0.6.zip` plus the included `parent-module.patch`, or apply the full 0.6 patch (but not both). The repository's original CppBridgeJ implementation is not replaced.
